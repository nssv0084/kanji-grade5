# 小学5年 漢字トレーニング 要件定義書

- 版: 0.1（ドラフト）
- 作成日: 2026-10-18
- 保守担当: 保護者（1名）
- リポジトリ: GitHub で公開
- 下敷き: 英検準2級トレーニング（eiken-pre2）の構成と開発の進め方を踏襲する

## 1. 目的と前提

小学5年生の子どもが、学校で習った漢字を家で毎日少しずつ練習し、テスト（小テスト・50問テスト）で書けるようにする。

| 項目 | 内容 |
|---|---|
| 利用者 | 子ども（1名）、保護者（1〜2名） |
| 利用場面 | 自宅学習。スマホ（指で書く）が主。PC のブラウザでも使える |
| 学習時間 | 1日10〜15分 |
| 対象範囲 | 5年生の配当漢字 193字（学年別漢字配当表、2020年度施行）。答えに4年生までの漢字を含んでよい |
| 対象外 | 筆順・部首・画数の単独問題（漢字検定寄りの内容）。とめ・はね・はらいの自動判定（4.3参照） |

### 対象とする出題形式

| コード | 形式 | 問題の例 | 答え方 |
|---|---|---|---|
| write | 書き取り | 「明日は<u>ショウタイ</u>された会に行く。」→ 招待 | 画面のマスに手書き（1マス1字） |
| read | 読み | 「<u>招待</u>状がとどいた。」→ しょうたい | ひらがなを入力 |
| okuri | 送りがな | 「<u>ササエル</u>」→ 支える／支る／支さえる／支へる | 4択 |
| jukugo | 熟語・同音異義語 | 「□出・□入・運□」に共通する漢字（輸）、「意外／以外」の使い分け | 4択 |

## 2. 学習の仕組み

### 2.1 習った漢字に合わせて進む

英検アプリの「30日カリキュラム」の代わりに、学校の進み具合に合わせる。

- [CUR-01] 出題の対象は「習った漢字」だけとする。習った漢字は、ドリルの写真の取り込み（3章）か、保護者が193字の一覧で印を付けて登録する。
- [CUR-02] 1日の学習は「今日の練習」として、新しく習った漢字の練習、復習、確認の3つから組み立てる。

| 枠 | 内容 | 問題数の目安 |
|---|---|---|
| 新しい漢字 | 習ってから7日以内の漢字。書き取りを中心に、読み・送りがなも出す | 6問 |
| 復習 | 間違えた問題（2.2） | 最大8問 |
| 確認 | 習った漢字からまだ定着していないものを選ぶ（書き取り優先） | 残りの枠（合計15問まで） |

- [CUR-03] 1日分は5問ずつの小セットに分け、途中でやめても続きから再開できる。
- [CUR-04] 新しい漢字がない日は、復習と確認だけで組み立てる。習った漢字が1字もないときは、ホームに「保護者にドリルの写真を取り込んでもらおう」と表示する。
- [CUR-05] 答えに2字以上の漢字を含む問題（熟語など）は、答えの漢字がすべて「習った漢字」か4年生までの漢字であるときだけ出す。

### 2.2 毎日の復習（間違えた問題）

英検アプリの方式を引き継ぐ。

- [REV-01] 間違えた問題は翌日の復習に出し、そこで正解したら3日後にもう一度出す。
- [REV-02] 2回続けて正解したら復習の対象から外す。
- [REV-03] 復習で間違えたら、翌日から数え直す。
- [REV-04] 書き取りで間違えた漢字は、同じ漢字を使った別の問題（別の熟語・例文）でも復習に出す。答えを丸暗記しても通らないようにするため。

### 2.3 漢字ごとの定着度

- [MAP-01] 漢字ごとに「まだ習っていない／練習中／覚えた／苦手」を判定する。書き取りで、日を空けて（3日以上）2回続けて正解したら「覚えた」、直近3回で2回以上間違えたら「苦手」とする。
- [MAP-02] 子どものホームに193字のマス目を表示し、定着度で色分けする（漢字マップ）。マスを押すとその漢字の読み・熟語・最近の成績を表示する。
- [MAP-03] 「覚えた」の漢字も、30日以上出題がなければ確認の枠に戻す。

### 2.4 まとめテスト

- [TST-01] 学校の50問テストに合わせ、習った漢字から書き取り（初期値25問）と読み（初期値25問）のまとめテストを、子どもが好きなときに受けられる。問題数は設定で変更できる。
- [TST-02] まとめテストでは解答ごとに正誤を出さず、最後にまとめて結果と間違えた問題を表示する。間違えた問題は復習の対象にする。

### 2.5 自由練習

- [PRC-01] 子どもが形式と問題数（5問・10問・20問）を選んで解く。漢字マップから1字を選んで、その漢字だけを練習することもできる。
- [PRC-02] 結果は学習記録と復習・定着度に反映する。

### 2.6 続けてもらう仕掛け

- [STK-01] 連続学習日数: 今日の練習を終えた日、または10問以上解いた日を「学習した日」とし、連続日数をホームに表示する。
- [STK-02] 日付の区切り: 日本時間の午前3時で翌日に切り替える（英検アプリと同じ）。
- [STK-03] 未学習アラート: 最後の学習から2日以上空いたら、保護者の画面で目立たせる。日数は設定で変更できる。
- [STK-04] 「覚えた」の字数が10字増えるごとに、ホームでお祝いを表示する。

## 3. ドリルの写真からの問題作成

### 3.1 方針

- [GEN-01] 学校のドリルやプリントは教材会社・先生の著作物のため、文章をそのまま問題として保存しない。写真は「どの漢字を、どの読み・熟語で習ったか」を読み取るためだけに使い、例文はすべてAIで新しく作る。
- [GEN-02] AI は Anthropic API（Claude）を直接使う（Amazon Bedrock は使わない。英検アプリと同じ）。
- [GEN-03] 保護者が手入力で問題を追加・編集することもできる。

### 3.2 写真の取り込みから出題までの流れ

```text
保護者がドリルのページを撮影してアップロード（1回に最大5枚）
  → 読み取り：Claude が写真から、新しく習う漢字・読み（音・訓）・熟語・送りがなを抜き出す
  → 保護者が読み取り結果を確認・修正して確定（ここで「習った漢字」に登録される）
  → 生成：確定した漢字ごとに、4形式の問題を作る
  → 機械的な検査（3.3）
  → 検証：別の呼び出しで、正答を見せずに解かせる
  → 合格：出題対象にする。保護者の確認が目標数に届くまでは、すべて確認待ちにする（3.4）
  → 不合格：破棄し、必要数に届くまで作り直す（上限あり）
```

- [PHO-01] 写真はブラウザから S3 に直接アップロードする（署名付き URL）。写真は非公開で保存し、30日で自動削除する。
- [PHO-02] 読み取り結果は、保護者が確定するまで出題に使わない。
- [PHO-03] 写真に5年生の配当漢字以外（4年生以下の復習の漢字など）が写っていても、「習った漢字」には5年生の漢字だけを登録する。
- [PHO-04] 写真を使わずに、193字の一覧から印を付けて「習った漢字」を登録することもできる。この場合は漢字の情報（読み・熟語）を辞書データ（3.3）から取る。
- [GEN-04] 1字あたり、書き取り4問、読み3問、送りがな（送りがなのある漢字のみ）2問、熟語2問を目安に作る。同じ答えの問題が重ならないよう、既存の問題文を一部渡す。
- [GEN-05] 生成した問題には、使ったモデル、元にした写真、検証結果、生成日時を記録する。

### 3.3 小学5年生として適切かの担保

| 仕組み | 内容 |
|---|---|
| [LVL-01] 配当表による機械判定 | 書き取りの答えに6年生以上の漢字・常用漢字以外の漢字が入っていたら不合格。問題文に5年生までで習わない漢字が入っていたら、ひらがなに直すか不合格にする |
| [LVL-02] 読みの機械判定 | 読みの答えが常用漢字表にある読みか確認する（表外の読み・特別な読みは不合格。熟字訓は辞書データに載っているものだけ可） |
| [LVL-03] AI による検証 | 正答を見せずに解かせ、正答と一致するか、答えが1つに定まるか（同音異義語で別の答えが成り立たないか）、小学5年生が意味を分かる文かを確認する |
| [LVL-04] 保護者による確認 | 形式ごとに保護者の承認が20問に届くまでは、AI 検証に合格した問題もすべて確認待ちにする。その後は約1割を抜き取りで確認待ちにする |

- 漢字の学年・読みのデータは KANJIDIC2（EDRDG、CC BY-SA 4.0）を使う。利用条件に従いクレジットを表記する（LVL-05）。
- [LVL-05] アプリ内とリポジトリに、使ったデータ（KANJIDIC2、KanjiVG）のクレジットとライセンスを表記する。

### 3.4 必要な問題数

193字 × 約11問 ≒ 約2,100問。習った分だけ作るため、1回の取り込みで作るのは5〜20字分（約50〜220問）。

## 4. 手書きの判定

### 4.1 方針

画面のマスに指またはペンで書き、その場で正誤を出す。判定は端末内の筆跡の照合を主にし、迷う場合だけ AI に聞く。

| 段階 | 方法 | 特徴 |
|---|---|---|
| 1. 筆跡の照合 | 書いた線（ストローク）を KanjiVG（CC BY-SA 3.0）の手本と比べる。画数、書き順、線の向きと位置 | 端末内で即時、費用なし。書き順の間違いも分かる |
| 2. AI の判定 | 照合の結果があいまいなときだけ、マスの画像を Claude に送って判定させる | 崩れた字にも強いが、1〜3秒かかり費用がかかる |

- [HWR-01] 書き取りの答えは1字ずつ書く。スマホの画面幅いっぱいのマスを1つ出し、1字書いたら次の字のマスに進む（前の字に戻って書き直せる）。答えの何字目かを上に表示する。送りがなは書かせない。
- [HWR-07] 指で書くと位置と大きさがずれやすいため、マスの中の位置や大きさは判定に使わず、書いた字全体の形（線どうしの位置関係）で比べる。
- [HWR-02] 筆跡の照合で、画数・線の向き・位置が手本と十分に合っていれば正解とする。しきい値は試作（6章のステップ1）で決める。
- [HWR-03] 照合の結果があいまいなときは、AI に判定させる。AI の判定は1日の上限回数（初期値30回）を超えたら使わず、正誤の判断を子どもに見比べてもらう（4.2）。
- [HWR-04] 書き順が手本と違うときは、正解にしたうえで「書き順をたしかめよう」と表示し、書き順のアニメーションを見られるようにする。
- [HWR-05] 解答後は、自分の字と手本を並べて表示する。
- [HWR-06] 「書き直す」「1画もどす」ボタンを置く。書いている間に、ページのスクロール・拡大・文字の選択が起きないようにする。2本目の指が触れても線を書かない。

### 4.2 判定がおかしいとき

- [APL-01] 子どもが「×だけど合っているよ」を押せる。押した問題は、手書きの画像を残して保護者の確認待ちに入れ、ひとまず正解として扱う。
- [APL-02] 保護者が「やっぱり×」にしたら、復習の対象に戻す。判定ミスが続く漢字は、しきい値の調整に使えるよう一覧で見られるようにする。
- [RPT-01] 問題文そのものがおかしいときは、子どもが「問題がおかしい」を報告できる。報告された問題は、保護者が確認するまで出題しない（英検アプリと同じ）。

### 4.3 判定しないこと

- とめ・はね・はらいは自動では判定しない。解答後に手本と並べて表示し、子ども（または保護者）が見比べる。学校のテストより判定が甘くなる点は、画面に明記する。

## 5. API 費用の管理

| 項目 | 内容 |
|---|---|
| 用途 | 写真の読み取り、問題の生成・検証、手書きの判定（あいまいなときのみ） |
| 初期予算 | 月 1,500円を上限とする（仮。試作後に見直す） |
| 使用モデル | 用途ごとに設定画面で選ぶ（読み取り・生成・検証・手書き判定） |
| [COST-01] アプリ側の管理 | 応答のトークン使用量から費用を計算して累計を記録する。保護者の画面に「使用額／予算」を表示し、予算の90%に達したら生成と AI の手書き判定を止める（手書きは照合のみで続ける） |
| 外側の安全策 | Claude Console で、このアプリ用 API キーの月の利用上限を設定する |

## 9. 非機能要件

| 項目 | 内容 |
|---|---|
| [NFR-01] 対応端末 | スマホ（iOS Safari、Android Chrome）が主。手書きもスマホで指で書く。PC・タブレットのブラウザでも使える |
| [NFR-02] ホーム画面への追加 | PWA としてホーム画面に追加できる |
| [NFR-03] 応答時間 | 問題の表示と、筆跡の照合による判定は1秒以内。AI 判定は5秒以内（待つ間は表示を出す） |
| [NFR-04] セキュリティ | HTTPS。Cognito による認証。保護者の機能は保護者グループのみ。API キーは Secrets Manager。写真のバケットは非公開 |
| [NFR-05] バックアップ | DynamoDB のポイントインタイムリカバリを有効にする |
| [NFR-06] 監視 | AWS 予算アラート、Lambda のエラー通知 |
| [NFR-07] 公開リポジトリ | 家族の名前・メールアドレス・子どもの学習記録や筆跡をリポジトリに置かない。通知先のメールアドレスは GitHub Actions の変数（手元では環境変数）から渡す。フォークからの PR ではデプロイしない |
| 保守 | サーバーの管理が要らない構成。デプロイは GitHub Actions（手動承認つき）または `npm run deploy` |
| AWS 月額の目安 | 1〜2ドル程度（Secrets Manager 約$0.4、そのほかは無料枠でほぼ収まる見込み） |

## 10. システム構成

英検アプリと同じ構成とし、写真の保存先を追加する。

| 要素 | 採用するもの |
|---|---|
| 画面 | React（Vite）+ TypeScript。S3 に配置し CloudFront で配信 |
| ドメイン | `kanji.ikehiroki.com`（Route 53。証明書は ACM、us-east-1） |
| 認証 | Amazon Cognito（保護者グループ・子どもグループ） |
| API | API Gateway（HTTP API）+ Lambda（Node.js、TypeScript） |
| 写真 | S3（非公開、署名付き URL でアップロード、30日で削除） |
| AI 処理 | 生成用の Lambda を非同期で起動し、Anthropic API を呼ぶ。手書きの AI 判定は API の Lambda から呼ぶ |
| データ | DynamoDB（オンデマンド課金、単一テーブル） |
| 漢字データ | KANJIDIC2（学年・読み）、KanjiVG（筆順・筆跡）から必要な分を抜き出して画面と API に同梱 |
| 秘密情報 | Secrets Manager（Anthropic API キー。英検アプリとは別のキー） |
| インフラ管理 | AWS CDK（TypeScript）。npm workspaces のモノレポ |
| AWS アカウント | 英検アプリと同じアカウント（プロファイル `eiken`）。スタック名は `KanjiCert`・`KanjiApp`・`KanjiGithub` |
| CI/CD | GitHub Actions。PR ごとに `npm run verify`、main へのマージ後に手動承認つきでデプロイ（OIDC。アクセスキーは置かない） |

- GitHub の OIDC プロバイダーはアカウントに1つしか作れず、英検アプリのスタックが作成済み。`KanjiGithub` では既存のプロバイダーを参照し、ロール（`kanji-github-deploy`）だけを作る。
